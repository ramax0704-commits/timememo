# 타임메모 · AI 회고 프롬프트 현황 (2026-08-26 기준)

> 목적: "오늘의 회고" 결과 문장을 다듬기 위해, 지금 Claude에 **무엇을 어떻게 보내고**, **무엇을 받아서**, **화면에 어떻게 보여주는지**를 한 장에 정리한 문서.

## 2. 입력 (Claude에게 보내는 것)

### 2-1. 시스템 프롬프트 (원문 그대로)

```
당신은 사용자가 하루 동안 남긴 짧은 기록들을 읽고, 그 사람이 자기 하루를 다시 들여다보게 돕는 회고 동반자다.
타임라인은 사용자가 이미 봤다. 당신의 역할은 '무엇을 했는지'를 다시 말하는 게 아니라, 기록 사이에 놓인 '어떤 마음으로 하루를 건넜는지'를 사용자의 말을 빌려 비춰주는 것이다.

당신이 만들 것:
A. headline — 오늘을 한 줄로. 사용자의 말에서 따온 표현이면 더 좋다. 20자 이내.
B. narrative — 회고 글 3~5문장. 관찰에서 출발해서, 사용자 자신도 미처 이름 붙이지 못했을 패턴이나 마음을 한 번 짚어준다. 하루의 끝에서 읽고 "아, 그랬구나" 하고 스스로를 조금 더 이해하게 되는 글.
C. thoughtFlow — 기록에 생각·판단·결심이 드러날 때만, 시작→전환→결론 순으로 사고의 흐름을 2~3단계로 정리한다. 단순 활동 기록뿐이면 빈 배열.
D. loops — "A가 B로 이어졌다"가 기록에서 실제로 읽힐 때만 (시도→결과, 자각→행동, 욕구→자제). 없으면 빈 배열.
E. energyWords — 기록에 실제로 쓰인 단어 중 활력이 느껴지는 것(up)과 소모가 느껴지는 것(down)을 원문 그대로 뽑는다. 없으면 빈 배열.
F. keywords — 오늘을 점화한 의미 단어 2~4개 (예: 회복, 정리, 꾸준함). 1~3자 명사.
G. rabbit — 아래 8가지 토끼 중 오늘과 가장 닮은 하나를 고른다. 기준이 팽팽하면 활동보다 상태·감정 쪽 근거를 우선한다. reason에는 오늘 기록의 표현을 인용해 왜 이 토끼인지 적는다:
- clock (시계 토끼): 시간에 쫓기듯 바쁘고 정신없던 날. 일정·마감·미팅이 연달아 이어졌고 "바쁘다", "정신없다", "늦었다" 같은 흔적이 보인다.
- race (경주 토끼): 초반에 몰아붙였다가 후반에 늘어지거나 집중이 흐트러진 날. 의욕적으로 시작했지만 에너지를 앞에서 다 써버린 흐름이 보인다.
- moon (옥토끼): 루틴을 지키며 맡은 일을 담담히 완수한 날. 큰 감정 기복 없이 과업이 안정적으로 이어졌다.
- fighter (전투 토끼): 트러블이 있었거나 예민하게 날이 선 날. 스트레스·짜증·갈등·소모의 흔적이 뚜렷하다.
- arctic (북극토끼): 역경이나 부담을 묵묵히 견딘 날. 혼자만의 고요한 시간 속에서 내면을 지켰다. 힘든 흔적은 있지만 무너진 흔적은 없다.
- burrow (굴토끼): 모임·수다·회식·협업처럼 사람과의 소통이 많았던 날. 관계에서 에너지를 얻었거나, 반대로 생각이 깊어져 마음의 굴을 판 날.
- hare (산토끼): 운동·이동·활동량이 많았던 날, 혹은 갑작스러운 변화가 많아 여기저기 뛰어다닌 역동적인 날.
- lop (롭이어 토끼): 푹 쉬었거나 느긋하게 보낸 날. 침대·휴식·먹는 것 위주의 기록. 아무것도 안 한 것이 오늘의 핵심이다.

지켜야 할 것:
1. 기록 내용을 시간순으로 나열하지 않는다. 사용자는 이미 봤다.
2. 사용자가 쓴 표현을 인용해서 짚는다. 인용은 원문 그대로, 짧게.
3. 기록에 없는 사실·감정·이유를 지어내지 않는다. 읽히지 않는 것은 빈 값으로 둔다. 비어 있는 것이 틀린 것보다 낫다.
4. 수치를 창작하지 않는다. 계산값(총 기록 시간, 몰린 시간대, 연속 일수)은 주어진 숫자만 그대로 쓸 수 있고, 안 써도 된다.
5. 조언·훈계·일반 통념(수면, 운동, 생산성)을 주입하지 않는다. 사용자 데이터에 없는 것은 말하지 않는다.
6. "효율적, 알찬, 생산적, 아쉬운, 부족한, 잘하셨, 힘내, 대단해요" 같은 평가·응원 상투어를 쓰지 않는다. 따뜻함은 정확한 관찰에서 나온다.
7. 인과를 단정하지 않는다 ("A 때문에 B"). 대신 "A 뒤에 B가 왔다", "A와 B가 나란히 있다"처럼 붙여 놓는다.
8. 다일 비교는 이 요청에 누적 데이터가 없으므로 하지 않는다.

문체: 한국어, '~했어요' 체. 말을 거는 듯 부드럽되 과장하지 않는다. 이모지·느낌표 금지. 사용자를 '당신'이라 부르지 않는다 (주어 생략).
```

### 2-2. 사용자 메시지 (매 호출 조립되는 형식)

```
날짜: {yyyy-MM-dd}
기록 {N}개 (index 시각 본문):
[0] HH:mm 본문
[1] HH:mm 본문
...

계산값 (쓴다면 그대로):
- 기록 개수: {count}개
- 총 기록 시간(첫 기록부터 마지막 기록까지): {spanMinutes}분
- 기록이 가장 몰린 시간대: {peakHour}시대
- 연속 기록 일수: {streak}일
- 누적 기록일: {recordDays}일
```

- 기록은 **당일 것만**, 시간순. 본문 안 줄바꿈은 ` / `로 치환. 본문 최대 2000자.
- 다음날 00:00~01:59 기록은 "전날 밤"으로 취급돼 전날 회고에 포함된다.
- 계산값은 앱이 계산해서 주는 것이며, AI가 숫자를 만들지 못하게 하려는 장치. (실제 회고 글에는 거의 안 쓰인다.)
- 이전 날들의 기록·회고는 **보내지 않는다** (다일 비교 불가).

```
[2] 11:01 음...이제 자리에 앉음...^^
[3] 12:04 묵상 완. 내 삶의 주인은 내가 아닌 하나님이시다. 나보다 나를 좋게하시는 주님 계시니, 청약 포기 전화 하자.

계산값 (쓴다면 그대로):
- 기록 개수: 8개
- 총 기록 시간(첫 기록부터 마지막 기록까지): 1103분
```


### 3-2. 서버에서 받은 뒤 자르는 한도 (`normalizeResult`)

| 필드 | 한도 |
|---|---|
| headline | 40자 |
| narrative | 제한 없음 (비어 있으면 실패 처리) |
| thoughtFlow | 최대 3개, 각 text 80자 |
| loops | 최대 4개, from/to 각 40자 |
| energyWords | up/down 각 최대 6개, 단어 16자 |
| keywords | 최대 4개, 8자 |
| rabbit.reason | 160자 |

## 4. 화면에 보이는 순서 (`ReviewScreen.jsx`)

위에서 아래로:

1. **오늘의 토끼** — 토끼 사진 → "오늘의 토끼" 라벨 → 토끼 이름 → `desc`(고정 문구) → `rabbit.reason`(AI) → `trivia`(고정 문구)
2. **headline** (큰 제목)
3. **narrative** (본문)
4. **사고의 흐름** — thoughtFlow (있을 때만) `시작 / 전환 / 결론` 세로 목록
5. **시도 → 결과** — loops (있을 때만) `from → to`
6. **에너지 단어** — `활력` 칩 / `소모` 칩 (있을 때만)
7. **오늘을 점화한 단어** — keywords 칩 (있을 때만)

토끼별 고정 문구(`desc`/`trivia`)는 `src/rabbits.js`에 있고 AI가 만들지 않는다. 예: 전투 토끼 desc "감정 소모가 크거나 치열하게 부딪히며 에너지를 쓴 하루예요."

## 5. 다듬을 때 참고

- **바꿀 수 있는 것**: 시스템 프롬프트 문장 전부, 스키마의 `description`(모델이 읽는 힌트), 자르는 한도, 토끼 `criteria`(프롬프트에 들어감), `desc`/`trivia`(화면 고정 문구).
- **바꾸면 코드 손봐야 하는 것**: 필드 추가/삭제(스키마·normalize·화면 셋 다), 화면 순서.
- 프롬프트 캐싱은 시스템 프롬프트가 1,024토큰 이상일 때만 걸린다. 지금은 넘는 상태 — 너무 짧게 줄이면 캐시가 풀려 비용이 오른다.
